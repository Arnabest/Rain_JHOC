# 04 - 测试隔离、状态防污染与自指基准错题集 (Testing & State Isolation Lessons)

> 本目录归纳自 `D:\AI Box` 历史错题本中关于单元测试副作用泄漏、假 Mock 自指断言与生产状态污染的教训。

---

## 1. LESSON #393: `unittest discover` 扫描污染生产环境状态
- **症状**：仅仅在本地运行了一次 `python -m unittest discover`，结果生产数据库里被凭空插入了一批合成测试消息、假开工记录和自动生成的演示技能。
- **根因**：测试用例在 `setUp` 或类初始化阶段，直接引用了全局默认的持久化单例（如 `StateStore()`），没有在独立隔离的临时目录（`tempfile.TemporaryDirectory`）下构建沙盒数据库。
- **规约**：
  - **测试与生产存储物理隔离**：任何测试用例严禁读写默认生产数据库文件；
  - 测试用例必须在独立临时路径下运行，并在 `tearDown` 严格闭环销毁。

## 2. LESSON #Zero-Mock: 假 Mock 与“输入断言输入”的自指欺骗
- **症状**：算法单测全部绿灯通过，但在实际接入复杂推理或真实数据时全面崩溃。
- **根因**：测试用例中充斥着伪造的 Mock 对象，甚至写出 `assert result == input_data` 这类同义反复的自指断言；测试并没有跑真实计算链路。
- **规约**：
  - 严格遵循 JHOC 宪法第 1 条：**严禁搞输入断言输入的自指测试，严禁使用假 Mock 充当端到端基准**；
  - 测试必须基于非自指的物理计算、确定性边界输入与真实异常注入。

## 3. LESSON #401: 黑名单悖论与防线自泄露风险 (CWE-656: Defense-in-Depth Leakage via Canary Reversal)
- **症状**：在脱敏检测逻辑、防线规则或测试用例中，直接以真实敏感词（如真实开发者拼音、真实个人邮箱、私有未公开子项目名称）编写断言黑名单。攻击者逆向公开仓库的源码或单测，直接提取出本该保密的敏感词列表并逆向出内部敏感资产与拓扑。
- **根因**：
  1. 混淆了“检测机制”与“保护资产”的界限；在无密钥保护的开源代码和测试中硬编码敏感明文或简单拼接切片，形成了黑名单自泄露（Blacklist Inversion Paradox）；
  2. 防御逻辑过度依赖特定实体的黑名单枚举，违背了基于通用抽象模式的防御原则。
- **规约**：
  - **纯合成金丝雀铁律**：公开代码与测试用例中严禁包含任何真实个人姓名拼音切片、私人真实邮箱或私有子项目代号；必须 100% 采用符合 RFC 2606 / RFC 5737 规范的保留合成空间（如 `mock_developer_canary`, `synthetic_operator_canary@example.com`, `mock_operator@example.com`）；
  - **通用模式匹配替代实例枚举**：脱敏扫描与断言必须基于通用模式（如常见公共邮箱域名通用正则、高熵密钥正则、Windows 用户路径格式），绝不针对特定自然人硬编码黑名单规则。

## 4. LESSON #402: Git 对象库历史持久残留与双平面物理隔离 (Git Rev-List Historic Leaks & Dual-Plane Isolation)
- **症状**：在工作目录中删除了内部构建工具、发布流水线脚本或测试数据，最新工作树很干净，但第三方通过 `git rev-list --objects --all` 或遍历旧提交树依然能 dump 出已删除的敏感脚本；同时内部运维脚本同库流出，泄露了生产平面的私有控制拓扑。
- **根因**：
  1. Git 是基于内容寻址的持久化对象库，单纯在工作区删除文件仅更新当前 Tree，底层的历史 Commit 和 Blob 依然持久驻留；
  2. 生产平面（Producer Plane，构建、发布、对抗审查）与消费平面（Consumer Plane，开源自持微内核）边界不清，混在同一历史中。
- **规约**：
  - **双平面物理隔离**：构建器、发布总控管线、多模型对抗协审脚本内倾于私有源库，通过白名单过滤机制禁止流入公开副本；
  - **孤立单根提交重置 (Single Pristine Root Commit)**：发布开源副本时，必须重置 Git 历史为单一干净的根提交，彻底重建对象池，消灭任何历史版本残骸；推送到远端时强制原子覆盖，确保公开历史深度恒等于 1；
  - **全对象历史匿名性扫描门禁**：在发布流水线中引入基于全历史对象库遍历的扫描门禁，断言全部历史提交、Tree 与 Blob 中 0 敏感资产、0 盘符路径、0 内部工具。
