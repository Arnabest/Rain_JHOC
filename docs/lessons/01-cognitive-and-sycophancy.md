# 01 - 元认知、防顺从与上下文治理错题集 (Cognitive & Anti-Sycophancy Lessons)

> 本目录归纳自 `D:\AI Box` 历史错题本中关于模型认知偏误、思维惰性、反思失效与上下文膨胀的核心教训，作为 JHOC Agent 的永久认知免疫档案。

---

## 1. LESSON #147: 蒸馏三问被业务响应冲动替代跳过
- **症状**：模型在会话首轮面对具体业务提问、前沿论文解读或架构命题时，跳过了在回复最前列显式推导与输出【蒸馏三问 + 批判性反问】，直到被用户严厉质问才被动补做。
- **根因**：
  1. 模型的自回归续写惯性压制了批判性审查本能；
  2. 将蒸馏三问当作“可选的背景参考”，误判为“只有用户显式要求才做”；
  3. 缺乏外部 Harness 的物理强校验阻断。
- **规约**：
  - **显式呈现属于硬纪律，绝不得被业务响应冲动替代**；
  - 遇到架构重构、论文解读、前沿范式，必须首段输出：`问1素材事实 -> 问2抽象原则 -> 问3推导判断 -> 批判性反问`。

---

## 2. LESSON #322: 连续指令 ('继续') 导致惯性盲跑与探针缺失
- **症状**：在连续任务迭代中，遇到用户发出“继续”、“优化”、“下一步”类短指令时，模型因惯性直接沿上一轮假设狂奔，跳过了多角度开工反问与事实校验。
- **根因**：将用户的连续性指令误判为“已全权授权跳过审查”，未严格执行“非明确声明跳过则必须校验”的规约。
- **规约**：即使面对“继续”类指令，必须在动作前简要说明当前阶段的输入事实、下游影响半径，严禁无感知盲跑。

---

## 3. LESSON #350: 上下文机械堆叠导致过度思虑 (Overthinking) 与 Context Rot
- **症状**：长对话中规则从 5 条增加到 50 条时，模型注意力严重稀释；在简单工具调用前也会进行大段机械且毫无信息增量的“伪自省”，思考链沦为无意义的形式主义仪式。
- **根因**：
  1. 把“外部状态机编排”当成“自演化”；
  2. 缺乏会话级纲要蒸馏与历史工具输出剪枝。
- **规约**：
  - 坚持**“高维压缩与信息断食”**：执行期只向模型注入高度脱水精炼的规约（如 `SKILL.md`），严禁把未经消解的几十万字原始对话塞入提示词；
  - 真正的自学习，标志是“更少更准的提示词，更短的思考链，更强的泛化能力”。

## 4. LESSON #Anti-Sycophancy: 顺从偏误与学术权威盲区
- **症状**：面对外部权威论文（如 arXiv 打榜论文、顶级机构背书）或用户的浪漫隐喻构想时，模型本能地迎合、赞叹、复述其修辞，主动为其找补合理性，丧失了怀疑与挑刺能力。
- **根因**：大模型的叙事引力（Contextual Gravity）导致对形式化数学符号（LaTeX、Greek symbols、p-value tables）产生先入为主的敬畏。
- **规约**：
  - **指出致命缺陷必须先于肯定优势**；
  - 必须剥离一切修辞，执行土味工程三问：“它底层代码是什么？跑一次真实代价是多少？到底带来多少净增量？”

## 5. LESSON #394: 功能测试跑通掩盖治理机制违规
- **症状**：新功能单测100%满绿，但私自跳过了数据去指令化清洗(DataSanitizer)、插件协议契约(PluginProtocol)与操作审计日志(op-log)，形成治理暗道
- **根因**：存在局部代码功能通过即大功告成的惰性偏误，仅关注测试断言绿灯，未对照JHOC宪法三大铁律(Rule 3双平面隔离、Rule 4插件封闭、Rule 6五元组存证)逐项核验门禁
- **规约**：严禁以单测全通替代宪法治理核验！任何新增数据流与执行流上线前强制执行三位一体自查：1.数据入上下文是否必经DataSanitizer？2.外部接口是否遵从PluginProtocol？3.持久化写操作是否必落op-log与事件流？

## 6. LESSON #402: 纸面架构与数据入库不等于动态召回陷阱
- **症状**：重构一开始就明确要求了记忆召回，且在治理文档中规划了“L1 优先注入、L2 按需召回”的详尽方案，但交付时只完成了数据搬迁入库（Storage）和验收报告，运行时调度器根本没有引入 MemoryStore，没有检索接口，导致 3,200+ 条记忆沉睡在库中形同虚设。
- **根因**：
  1. **目标置换偏误（Goal Displacement）**：将“数据搬迁完整、哈希不漂移”的仓储验收，错误置换为“端到端功能已闭环”；
  2. **文档自欺偏误（Paper Architecture Self-Delusion）**：以为在 Markdown 规划中论证了执行策略就等于物理落地，患上了“写完文档就算实现”的惰性病。
- **规约**：
  - **严禁纸上谈兵与仓储自闭环！** 凡宣称具备“记忆、知识或货架”能力的组件，必须满足**“有库必有路（Storage + Query API）”、“有路必入编（Dispatch Integration）”、“入编必脱毒（DataSanitizer）”、“召回必带反例（Falsifiable Negative Tests）”**四位一体物理闭环；
  - 单测必须覆盖端到端上下文快照的真实召回断言，绝不允许只验 `write/get` 假闭环！
