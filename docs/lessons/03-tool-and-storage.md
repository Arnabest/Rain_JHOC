# 03 - 工具执行、字符清洗与存储契约错题集 (Tool & Storage Lessons)

> 本目录归纳自 `D:\AI Box` 历史错题本中关于工具静默失败、字符编码清洗、文件状态假成功与环境变量覆盖的教训。

---

## 1. LESSON #1: 工具未注册导致静默失败与假等待
- **症状**：Agent 在回复中声明“我来识别/我来处理...”之后，控制台陷入彻底死寂，无任何反馈输出。
- **根因**：目标工具未在系统调度中心注册，模型尝试现场跑 `python -c` 但环境无权限，导致异常被静默吞没。
- **规约**：
  - 工具调用前必须进行严格的显式注册与静态契约声明；
  - 必须为每个长耗时操作提供状态反馈，绝不产生无输出的静默挂起。

---

## 2. LESSON #88: 文本清洗将标准 CJK 标点误转为 ASCII 导致语义降级
- **症状**：中文 OCR、文档或代码注释中的全角中文标点被粗暴替换为 ASCII 标点（如 `作者认为,`、`定价:`），甚至将中文省略号 `……` 截断为半角单点，破坏可读性。
- **根因**：将“全角转半角”误作为通用清洗规则，没有区分 CJK 排版标点和无意义的连续 ASCII 噪声。
- **规约**：
  - 默认保留合法 CJK 排版标点：`，。；：（）……「」『』【】《》`；
  - 仅对明显的冗余 ASCII 符号（如 `!!!!`、`....`）进行规范化折叠。

---

## 3. LESSON #89: 诊断工具只读原始配置文件，遮蔽了运行态环境变量覆盖
- **症状**：用户明明在环境变量中配置了模型端点与 API 覆盖，但系统诊断报告依然显示原始 `config.toml`，导致排查方向完全南辕北辙。
- **根因**：运行时实际读取了覆盖链，但诊断展示代码却偷懒只读取了静态配置文件（违反了“读实际生效值”原则）。
- **规约**：
  - 一切系统状态诊断必须展示 **Effective Value（最终生效值）**，并附带原始配置与环境变量溯源链。

---

## 4. LESSON #96: 进程退出码 0 但产物为空的“假成功陷阱”
- **症状**：外部任务脚本执行完毕，退出码为 0，UI 和调度器直接判定任务成功，但下游消费者读取目标文件时报空文件或文件不存在。
- **根因**：将“进程正常退出”简单等同于“业务产物生成成功”；部分第三方工具在发生内部错误时未设置非零退出码。
- **规约**：
  - **产物验证优先于退出码验证**：任务成功与否必须基于对最终产物的硬检查（文件是否存在、大小是否大于 0、数据行数是否非空）。

---

## 5. LESSON #148: 在生成的文件、日志或对话输出中滥用 Emoji 表情符号
- **症状**：模型在对话输出、Markdown 报告、日志文件或代码注释中习惯性引入装饰性 Emoji 表情（如状态球、指示箭头、表情符号），在 Windows GBK 控制台、CLI 诊断或跨进程消息管道中触发 `UnicodeEncodeError` 崩溃或字符乱码破坏。
- **根因**：
  1. 大模型受预训练语料的装饰性修辞引力影响，在规则未显式物理压制时本能滑向花哨输出；
  2. JHOC V5 重构初期将该规则遗漏在宪法之外，缺乏全局物理约束。
- **规约**：
  - **全链路零 Emoji 铁律（Zero-Emoji Discipline）**：严禁在任何回复输出、Markdown 文档、代码注释、脚本日志与配置文件中使用任何高位 Unicode Emoji 字符；
  - 状态指示一律使用标准纯文本或 ASCII 标记替代：例如使用 `[PASS]`, `[WARN]`, `[FAIL]`, `[INFO]`, `->` 等，保持输出极致纯净。
