# 三维影响路径推演分析协议 (Impact Analysis Protocol)

> **核心戒律**：改动任何核心代码、配置或架构前，必须锚定目标节点，显式执行 DOWN / UP / FORK 三维影响路径推演，严禁局部敲击盲跑引发全局连锁崩溃。（反思 Rule 0）

---

## 1. 三维影响路径定义

| 维度 | 分析对象 | 核心核查问题 |
| :--- | :--- | :--- |
| **DOWNSTREAM (下游调用)** | 谁在消费此模块？ | 改动此函数入参/返回类型，下游有多少调用点会静默损坏？外部协议或快照是否兼容？ |
| **UPSTREAM (上游依赖)** | 此模块依赖谁初始化？ | 该改动是否引入反向依赖或循环导入？上游配置注入与生命周期是否在修改前生效？ |
| **FORK (分叉与并发状态)** | 存在哪些分支路径？ | 跨进程/跨实例是否存在并发争抢？持久化回滚或异常降级分支是否保持幂等与安全？ |

---

## 2. 操作规范

1. **改动前推演**：在重大修改前，必须在思考或回复中简述该改动对下游接口、上游依赖及失败分支的影响半径；
2. **改动后全链复核**：代码修改完成后，不仅要测试修改的单元本身，还必须重跑全局单测矩阵，验证下游关联组件未发生隐式破坏。
